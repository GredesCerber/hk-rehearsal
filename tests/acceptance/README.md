# tests/acceptance/

Приёмочные тесты по критериям приёмки задач. Builder пишет их **первым коммитом** своей задачи, до реализации.

- Один файл на задачу: `test_<issue>_<slug>.*` / `<issue>-<slug>.spec.ts`.
- Новые файлы добавлять можно. **Существующие** не меняются и не удаляются: проверка `hk-guard` отклонит такой PR.
- Исключение — задача, у которой в разделе «Меняет приёмку» перечислены эти файлы (поле `changes_acceptance` в PRD). Её пишет planner/analyst, обычно из фидбека людей («вход должен быть по телефону, а не по почте»).
- Ревьюер-агент проверяет, что каждый Given/When/Then задачи покрыт тестом и тест не подогнан под код.
- Для `risk:high` тесты пишет **другой агент** отдельной задачей в `tests/pending/<T>/` (CI их там не запускает). Исполнитель основной задачи первым коммитом переносит их сюда без изменений: `git mv tests/pending/<T>/* tests/acceptance/`.
